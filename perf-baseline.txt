# 勘定发现（P3 首轮；优化批次的靶单）：
#   ① **compact = 头号热点**：同语料 compact 15.7–17.9s vs expand 2.6–2.7s
#      ≈ **6–7×**——compaction 侧从无性能勘定史（J2 只勘了 expand 侧），首轮即
#      独大。优化批第一靶。
#   ② **fromRdf 高方差 + 超线性嫌疑**：n=4000 轮内 523–1344ms（±45%）；
#      n=20000 试测 13.7–37.8s（中位 25.4s）——缩放律存疑（线性 vs 二次），
#      留探针批专测。方差大 = GC/分配抖动面（与 J2「主成本 = 结构分配」同族信号）。
#   ③ **解析占比可忽略**：parse 9–10ms vs 管线 2.5–17.9s（<0.5%）——core 解析器
#      无辜（实测事实）。〔批2 勘正〕「J2『结构分配』结论推广到 compact 侧」系
#      推断，**已被批2 打点证伪**：compact 主成本 = O(P×T) 候选全量扫描（⑩），
#      非分配；expand 侧归属未下探（⑧）。
#   ④ **expand_nest 2000 别名 = 40ms 线性段**——J2 索引化修法（merge_property_values
#      槽位表）在多 nest 键场景保持线性，无回归迹象。
#   ⑤ canon bnode 链 1500 环 = 76ms——RDFC-1.0 在链形语料上便宜（n-degree 哈希
#      未爆）；碰撞组语料另立场景待下轮。
#   ⑥ **语义勘定副产品（@nest 别名序依赖）**：td 对象形 @nest 别名 + 前向引用
#      （别名定义在引用 term 之后）= 引擎拒（invalid @nest value）；别名前置或
#      简单形则过。官方套件无此形 oracle（tn 系全为已定义别名）⇒ 按「无 oracle

#   ⑦ deep 场景上限 = core @json.parse 默认最大嵌深 1024（J0 勘定的直接后果；

#   ⑧ **expand_wide 二次形状（批2 核③连带发现 → 批4 已修）**：20000→40000 =
#      4.8×/倍增。**批4 码级坐实 = ⑨ 同一码点**（见⑨）。

#      4000/8000/16000 = 48/154/582/2026ms（每倍增 ~3.5×）。**批4 根因坐实**：
#      expand_object 平铺属性合并（expand_standard.mbt:1257——壬子批 #t0034/
#      #t0114 同 IRI 单键累加）**逐键线性扫全量 properties ⇒ O(P²)**——J2 索引
#      化了 nest 合并（merge_property_values）却漏了此平铺点；⑧⑨ 同源。
