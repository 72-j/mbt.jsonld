# 勘定发现（P3 首轮；优化批次的靶单）：
#   ① **compact = 头号热点**：同语料 compact 15.7–17.9s vs expand 2.6–2.7s
#      ≈ **6–7×**——compaction 侧从无性能勘定史（J2 只勘了 expand 侧），首轮即
#      独大。优化批第一靶。
#   ② **fromRdf 高方差 + 超线性嫌疑**：n=4000 轮内 523–1344ms（±45%）；
#      n=20000 试测 13.7–37.8s（中位 25.4s）——缩放律存疑（线性 vs 二次），
#      留探针批专测。方差大 = GC/分配抖动面（与 J2「主成本 = 结构分配」同族信号）。
#   ③ **解析占比可忽略**：parse 9–10ms vs 管线 2.5–17.9s（<0.5%）——core 解析器
#      无辜（实测事实）。〔批2 勘正〕「J2『结构分配』结论推广到 compact 侧」系
#      推断，**已被批2 打点证伪**：compact 主成本 = O(P×T) 候选全量扫描（⑩），
#      非分配；expand 侧归属未下探（⑧）。
#   ④ **expand_nest 2000 别名 = 40ms 线性段**——J2 索引化修法（merge_property_values
#      槽位表）在多 nest 键场景保持线性，无回归迹象。
#   ⑤ canon bnode 链 1500 环 = 76ms——RDFC-1.0 在链形语料上便宜（n-degree 哈希
#      未爆）；碰撞组语料另立场景待下轮。
#   ⑥ **语义勘定副产品（@nest 别名序依赖）**：td 对象形 @nest 别名 + 前向引用
#      （别名定义在引用 term 之后）= 引擎拒（invalid @nest value）；别名前置或
#      简单形则过。官方套件无此形 oracle（tn 系全为已定义别名）⇒ 按「无 oracle
#      不扩」挂账不扩，仅记于此。bench 语料已按合规形（别名前置）构造。
#   ⑦ deep 场景上限 = core @json.parse 默认最大嵌深 1024（J0 勘定的直接后果；
#      depth>1024 的文档本库解析层即拒——容量边界，非缺陷）。
#   ⑧ **expand_wide 二次形状（批2 核③连带发现）**：20000→40000 = 4.8×/倍增
#      （40000 中位 13771ms）——expand 侧残留二次成分（J2 修了 @nest 合并点；
#      wide 形状的二次点未下探，留优化批勘定）。
#   ⑨ **expand_nest 二次形状（批2 核③「无回归」撤回）**：2000/4000/8000/16000 =
#      48/154/582/2026ms（每倍增 ~3.5×）。J2 后修读数 16000=51ms 不可直比
#      （原语料随探针删、形状不同）；本形状二次坐实，与⑧同族入靶单。
#      〔教训入册〕**单点读数定不了缩放律**——「无回归」类结论必带 ≥3 点缩放实证。
#   ⑩ **compact P4 根因（批2 码级坐实）**：`compact_term_candidates` 逐属性
#      **全量扫 active.terms**（compact_standard.mbt:22）——调用点 11 处（属性键
#      1295 / 值侧 compact_iri_word 78 / 精确哨兵 783、1000 / 反转 2005、2064、
#      2310、2528 等）+ compact_iri_word 最长前缀扫描（:109）同型。O(P×T) 量级
#      核算：20000 属性 × 20000 term = 4×10⁸ 串比较 × ~34ns ≈ 13.7s 与 P4 实测
#      吻合。修法方向（**优化批，本役不动码**）：IRI→term 名倒排索引**整段建一次**
#      （const §5 索引化纪律）——候选集等价 + 末段排序（容器缺省→短名→字典序）
#      保序即语义钉；前缀扫描（:109）另立 prefix-term 小索引或同源挂接；
#      ActiveContext 系 pub trait 签名件，索引挂接面立项时定（每次 compact_document
#      按需重建 O(T) 摊销即可行，无 struct 变更）。
